## 1. Durable intent before effect, receipt after observable completion

`createGoalRuntime` (`lib/goal-policy.mjs`) wires the accepted DUR-002 store, the
accepted DUR-004 executor, the authority broker, the ownership boundary and the test
runner into one path; `resume()` runs the executor's accepted sequence unchanged:
validate authority and preconditions, reserve in the ledger, append and sync the
intent, append the dispatch, perform the effect, append the receipt, then expose
completion. A journal/append failure therefore prevents the effect instead of being
swallowed. Regressions: `a disk failure before the intent prevents the effect`,
`a disk failure after the effect leaves a blocked, non-successful goal`.

Existing writers join the same rule through `withWorkspaceWriteLock`:

- `lib/controller.mjs`: `undoLast` is a mutation, so it now runs inside
  `withWorkspaceWriteLock(undoRoot, ...)`; an active durable goal refuses undo with
  `{ ok: false, error }` instead of restoring over its bytes. Lock/probe refusals
  are surfaced as errors; anything else still throws.
- `lib/local-agent.mjs` hooks: both apply branches perform
  `revalidateBeforeWrite` + `backupFile` + `writeFileAtomic` inside
  `withWorkspaceWriteLock(project.root, ...)`, preserving exact backup/undo
  integrity and bytes.
- `lib/model-agent.mjs` (declared handoff above): same wrapping in both write
  branches.

## 2. Approval bound to operation + workspace + generation; restart expiry; independent approvals

`createGoalAuthority` is the decision broker for one invocation:

- A pre-issued grant is keyed by the SHA-256 of the canonical `[kind, path,
contentSha256]` (edit) or `[kind, planHash]` (test), so a decision binds one exact
  proposal. `assertOperationBinding` validates `goalId`, `attemptId`, `generation`,
  `operationId`, `planHash`, and for edits `path` + `contentSha256` on every
  `authorize*()` call, and every audit event records the workspace identity
  (path/device/inode). Authority is collected one step before dispatch by the trusted
  adapter and consumed one-shot inside the dispatch gate; a proposal with no
  pre-issued grant and no invocation-scoped flag is denied — the gate never
  fabricates authority.
- Every decision and grant is appended to the run log (`goal:decision` /
  `goal:grant`, `requireComplete`); a grant whose audit cannot be persisted is not
  issued (fail closed, nothing granted).
- **Restart expiry:** grants and flags live only in the invocation's memory and are
  never persisted as authority; a fresh process starts with none. `allowEdits`
  mirrors standalone `--yes` (edit-only, this invocation); `allowTests` mirrors
  `--allow-tests` (exactly one exact plan per invocation, spent after use). Tests:
  `a fresh invocation cannot replay the old invocation's approval`, `the headless
edit allowance survives only within its own invocation`, `a headless allowTests
grant covers exactly one plan per invocation`.
- **Independent approvals:** edit, test and command are separate kinds with separate
  grant keys and separate audit entries (`edit and test approvals are independent of
each other`); Ctrl+C at the approval prompt registers a denied grant, so the
  operation is denied durably (`Ctrl+C at approval denies the operation`).
- Regressions: `a denied edit produces no durable intent, no bytes and a safe stop`,
  `an approved edit is bound to the exact operation, workspace and generation`.

## 3. Cross-process lease and pidfd-based process ownership

- The store lease now carries an owner identity `{ pid, startTime, bootId }`
  (validated by `validateAttemptOwner`/`validateGoalLease`; renewal requires the
  identical identity), so a lease is owned by one exact task on one boot, not by a
  bare pid.
- `reclaimStaleGoalAttempt` releases an abandoned lease only after verified owner
  death: under the goal lock with a fence it re-inspects, requires the host boot id
  to match (a boot/host mismatch refuses without touching anything), and treats the
  owner as dead only when the pid is absent, its start time differs (pid reuse), or
  it is a zombie. `store.reclaimAttempt` then clears the lease and marks the attempt
  interrupted. Reclaim never grants authority, never retries operations and never
  releases a teardown block. Test: `reclaim succeeds only after the owner is
verifiably dead`.
- **Process ownership:** `createExecutionOwnership.recordDispatch` persists an
  atomic private ownership record per dispatched operation at spawn (mode `0600`,
  write + fsync + rename + directory fsync), carrying `bootId`, `machineId`, `pid`,
  `pgid`, `startTime` (read from `/proc/<pid>/stat` field 22), `startedAt` and the
  canonical workspace identity; the recorded pgid is cross-checked against `/proc`.
- Verification and teardown go through the reviewed C helper
  `scripts/matrix-pidfd-helper.c`, built per machine by
  `scripts/build-pidfd-helper.mjs` into `MATRIX_HOME/bin` (static preferred, `-Werror`,
  self-probe on install; not shipped in the package because the pack allowlist
  carries `.mjs` sources only). Node has no pidfd binding, so the helper pins a
  `pidfd_open` first, re-reads `/proc`, compares boot id, start time and pgrp, and
  only then `pidfd_send_signal`s — a bare pid is never signalled on name alone, a
  start-time mismatch (pid reuse) is never signalled (exit 3), and a boot-id
  mismatch is fatal. Until the helper is built, verification fails closed
  (`ownership-helper-unavailable`), nothing is signalled, and Doctor reports the
  capability unavailable.
- `verifyAndTeardownTree` first walks the recorded leader's descendant tree through
  `/proc` parent links and refuses with `survivor-escaped-group` when any descendant
  runs in a process group other than the recorded pgid (a `setsid()` escape), then
  enumerates the recorded process group (excluding self and ancestors up to 64
  levels), refuses members that predate the recorded group leader, treats zombies as
  gone, SIGKILLs surviving members through the helper with a bounded wait, and
  accepts a host reboot (same machine id, new boot id) as definitionally torn down.
  Tests: `a pid reused by an unrelated process is never signalled`, `a host or boot
identity mismatch refuses attestation`, `an escaped descendant is never certified
as stopped`, `goal test dispatch refuses before starting an uncontained process`.

## 4. PID-namespace containment and teardown-unverified block release

Goal tests execute only inside a pinned Bubblewrap PID namespace
(`lib/goal-containment.mjs` spawns bwrap as the monitor; the namespace init is
Bubblewrap's reaper, NSpid 1; `lib/goal-guardian.mjs` waits for a host-owned
gate). `createExecutionOwnership.pinContainment` pins the monitor, init start
times and the namespace inode (`/proc/<init>/ns/pid`) before the dispatch
record is persisted and the gate is released, so no repository code runs
unrecorded. Records also carry `containment: { kind: "pid-namespace",
namespace, monitor, init }`. Normal completion, timeout and cancellation all
settle the exact namespace through the pidfd helper (killing namespace init
stops every member, including `setsid()` escapees) before the runner reports;
the monitor exiting first does not count as teardown. Dispatch and
verification refuse unless both the pidfd helper and a real bwrap namespace
probe pass (`containmentUsable`); Doctor's `goal-ownership` check mirrors
this and never claims containment from a pidfd probe alone. Legacy
process-group records keep the fail-closed `survivor-escaped-group` refusal.

The accepted DUR-004 workspace-scoped `durableExecutionBlock` is consulted before
any admission; the only release is the trusted `executionOwnership.verifyTeardown`
attestation, never elapsed time, a PID table or a settled adapter promise.
`verifyTeardown` covers every blocked operation exactly once with matching attempt,
generation and workspace identity; on success it persists a durable reconciliation
record per operation (`ownership/reconciled/<operationId>.json`, mode `0600`) so
later invocations reuse it through a strictly bound fast path, while a present but
mismatched reconciliation releases nothing. Every reconciliation record also
carries `helperSha256` — the sha256 of the reviewed helper binary at
`MATRIX_HOME/bin/matrix-pidfd-helper` (private `0700` bin dir, owner-owned
`0700` file) — and both the fast path and `lib/goal-lease-probe.mjs` accept only
mechanisms in `{ pidfd-teardown, already-exited, host-reboot }` whose
`helperSha256` equals the digest of that exact installed binary, and (except
for a same-host `host-reboot`) whose namespace identity equals the ownership
record's, so trust is bound to the reviewed verification mechanism and a
swapped or legacy process-group-only record releases nothing. The attestation
shape is exactly the one the accepted executor requires (`operationId`,
`attemptId`, `generation`, `mechanism`, `ownership: { pid, startTime,
bootId }`). The test runner (`createGoalTestRunner`) re-inspects the approved
plan at dispatch time (a changed executable, argv or package script spawns
nothing), runs it through the containment runner with `onPin` bound to
`recordDispatch`, and reconciles the operation after the run so its ownership
record does not block the goal's own next operation; a recording failure
throws so the executor marks the execution unverified (durable block)
instead of reporting a plain failure.

## 5. Ordinary-writer workspace authority probe

`withWorkspaceWriteLock` (`lib/workspace.mjs`) now runs
`assertNoDurableGoalOwnsWorkspace` (`lib/goal-lease-probe.mjs`) before any
cooperating writer mutates the workspace. The probe refuses when a goal bound to the
same canonical workspace identity (path, or device/inode) holds a live foreign lease
(not expired and not the caller itself by pid + start time + boot id), or when an
ownership record for that workspace has no matching reconciliation record. It is
fail-closed: any unreadable, untrusted or corrupt durable state (including checkpoint
checksum and canonical-byte verification) refuses with `DurableGoalUnsafeError`
rather than risk a bypass; it never writes and never signals, and its messages carry
no file bytes or credentials. The goal's own process is recognized (pid + start
time + boot id against a live lease on the same workspace), so the owning goal is
neither blocked by its own lease nor by the ownership records it wrote while
holding that lease; every other writer stays blocked while an unverified execution
may survive. Controller undo, both local-agent
branches and both handed-off model-agent branches all join through this lock; the
verified lease-reclaim path uses the reserved `skipDurableProbe` option. Tests:
`ordinary writers are refused while a durable goal owns the workspace`, `a corrupt
durable goal state refuses ordinary writers`.

## 6. Unsupported command refusal

`authorizeCommand` always throws `GoalCommandUnsupportedError`
(`goal-command-unsupported`): "the durable goal workflow does not support
run_sandboxed_command or any command tool; existing standalone command behavior is
unchanged". The goal workflow exposes no command capability; standalone
`run_sandboxed_command` behavior outside it is untouched (test: `ordinary standalone
command behavior is unchanged`, plus `the durable workflow refuses command tools with
a clear error`).

## Known limitations

- **No failing tests at submission time**; the full suite is 990/990 on Node
  v24.21.0 and Node 22.23.1 (see Verification).
- **Live engine wiring is DUR-006.** `createGoalRuntime` requires a scripted or
  adapter engine; live provider engines, CLI and UI continuation attach by the
  caller. Existing engine outcomes are preserved (no engine file behavior changed
  beyond the handed-off lock wrapping).
- **The pidfd helper is per-machine.** Until `node scripts/build-pidfd-helper.mjs`
  has run, durable-goal teardown verification fails closed and nothing is signalled;
  Doctor reports the capability as unavailable. Non-Linux platforms refuse (the
