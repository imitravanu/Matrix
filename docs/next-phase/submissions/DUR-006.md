## Delivered behavior

- `matrix goal start|resume|pause|cancel|list|inspect` uses the accepted goal runtime. List and inspect only read persisted state and workspace evidence. Existing session `--resume` remains available.
- Start validates versioned criteria and limits. Resume uses the saved workspace identity, provider binding and cumulative budget. It requires fresh invocation authority for effects. A separate process requests pause or cancel through a private Unix socket bound to the exact live owner and lease generation.
- A terminal displays remaining criteria, budget, last durable operation, stop reason and continuation command. It prompts for exact edit and test approvals. Headless `--yes` authorizes edits for that invocation. `--allow-tests` separately authorizes the bound test plan through the accepted contained runner.
- Human decisions are recorded by terminal input after the machine criteria are met and are bound to the goal, criterion revision and tracked source fingerprint. Valid saved decisions can be used after restart.
- Workspace-mismatch guidance names the recorded workspace in JSON and terminal output. While that path still resolves to the recorded device/inode, the continuation is a copyable `matrix goal resume <id> --cwd '<path>'`; when the path is missing or replaced, the output names the recorded path, explains how to locate the original directory and never points a resume at a replacement. Printed paths use shell quoting and credential redaction; if the raw workspace path contains credentials, it is omitted with `[redacted]` and safe recovery instructions are provided to run from the original recorded workspace.
- `pause` and `cancel` against a lease that is not a verified live owner exit `2` with `result: refused`, the existing reason and a `matrix goal resume <id>` recovery command. Lease verification is unchanged and a refusal mutates no goal state.
- CLI output distinguishes fresh start, resumed and reconciled attempts, and completion. Exit codes are 0 for completion or successful read/control, 1 for incomplete work, 2 for invalid or refused requests, and 130 for interruption.

## November 8 repair

The independent review issued **CHANGES REQUIRED** for Finding 1 (`P2`) and asked
for Finding 2 (`P3`) to be fixed in the same pass. The subsequent re-review
issued **CHANGES REQUIRED** for Finding R1 (`P2`, credential redaction in guidance).

1. **Workspace-mismatch recovery guidance (Finding 1).** `inspect` from a foreign
   directory reported that the recorded identity had changed and then suggested a
   continuation rooted at the current (wrong) directory; `resume` refused without
   naming the recorded path. The projection now resolves the recorded path and
   distinguishes the two cases. If the path still resolves to the recorded
   device/inode, the reason names that path and `nextCommand` is the copyable
   `matrix goal resume <id> --cwd '<path>'`. If it is missing or replaced, the
   reason names the recorded path and explains how to find the original
   (`matrix goal list --cwd <new directory>`, then resume only from the directory
   that lists the goal); `nextCommand` is `matrix goal inspect <id>`, so no
   replacement directory is ever targeted. The same wording backs the `resume`
   refusal. Locally constructed guidance is redacted as trusted text, so the
   recorded path can never cause the whole message to be withheld, while a path
   containing the credential is still redacted and loses its `--cwd` suffix.
2. **Stale-owner control refusal (Finding 2).** `pause` and `cancel` against a lease
   that was not a verified live owner threw a plain error, which the CLI mapped to
   exit `1` for non-`start` actions, contrary to the documented exit `2` for
   refused requests, and the message named no recovery. Both refusal branches now
   raise the invalid-request class, so JSON and terminal output report
   `result: refused` with exit `2` and name `matrix goal resume <id>` (and
   `matrix goal inspect <id>`). The verified-owner socket path, lease checks and
   refusals are unchanged; the refusal is raised before any store mutation.
3. **Workspace path credential redaction and custom auth.env resolution (Finding R1).**
   The re-review found that shell quoting the recorded workspace path before
   redacting caused credentials containing single quotes (`'`) to be escaped into
   `'"'"'`, preventing substring redaction matching. Furthermore, the redactor
   constructed on inspect and resume refusal only collected environment variables
   matching sensitive naming heuristics, omitting valid provider credentials
   configured under custom `auth.env` names (such as `FOO`).
   The repair:
   - Resolves provider secrets offline and read-only from `providers.json` and
     environment variables via `resolveGoalSecretValues` for both explicit
     builtin and custom `auth.env` configurations, immediately upon inspecting
     the persisted goal.
   - Inspects the raw workspace path for secrets using `isSensitivePath(path, redactor)`
     before any shell quoting occurs.
   - If sensitive, the path is omitted from the mismatch reason with `[redacted]`
     and the user is instructed to run the printed command from the original
     recorded workspace; `withWorkspace` drops `--cwd` completely.
   - If safe, the path is shell-quoted with single quotes, preserving the copyable
     `--cwd '<path>'` continuation (including paths containing apostrophes).
   - Both inspect (JSON and terminal output) and resume refusal (JSON and terminal
     stderr) are completely stripped of raw and shell-escaped credentials while
     keeping inspect and refusal strictly read-only and offline.
   - Added focused regressions in `test/goal-cli.test.mjs` checking both JSON
     and terminal output for custom `auth.env` names, quote-bearing credentials,
     and safe paths with apostrophes as a control.

Alternate counterexamples from the same failure families are covered, not only
the review reproductions: a moved directory (same identity) recovers with a resume
from the new location; a replacement directory at the recorded path stays refused
and is never named as a resume target; a workspace path containing a single quote
is shell-quoted so the printed command receives one argument; a path containing
the credential is redacted and never printed; and a lease naming a live but
unrelated process (matching pid, wrong start time) is refused identically to a
dead owner, with the checkpoint and journal byte-identical afterwards.
