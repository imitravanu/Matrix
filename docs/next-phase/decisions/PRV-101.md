# PRV-101 decision record

Status: frozen contract, implemented in this candidate. Baseline `e1b3c66`.
Owner: chief/contracts implementer. Review: chief self-review only; **not** an independent
audit (PRV-106 must reproduce the security cases independently).

This record pins the executable interfaces consumed by PRV-102 (transport), PRV-103
(catalog), PRV-104 (CLI/UI/session), PRV-105 (probes) and PRV-106 (audit). Deviations
require a new decision record and chief review.

## 1. Files and ownership

| Path                               | Purpose                                                   |
| ---------------------------------- | --------------------------------------------------------- |
| `lib/provider-contracts.mjs`       | Pure validation, identity, digests, selection precedence  |
| `lib/provider-config.mjs`          | Private home file load, mutation, lock, atomic write      |
| `test/provider-contracts.test.mjs` | Table-driven validation, precedence, digest canaries      |
| `test/provider-config.test.mjs`    | Bounded load, atomic mutation, lock/liveness, size limits |

Public mutation surface: `addProviderProfile`, `replaceProviderProfile`,
`removeProviderProfile`, `addProviderModel`, `removeProviderModel`; each returns a promise
of `{path, config, digest}` and accepts `{home, expectedDigest, lockTimeoutMs}`.
`acquireProviderConfigLock`/`releaseProviderConfigLock` are asynchronous and exist only for
tests.
Listing/showing profiles is a projection over `loadProviderConfig()` in PRV-103/104;
PRV-101 deliberately adds no duplicate reader.

No caller is migrated in PRV-101. The existing legacy resolver in `lib/models.mjs` and
the credential lookup in `lib/credentials.mjs` remain untouched so Local Forge,
OpenRouter and Ollama behavior is unchanged until PRV-102/104 consume these exports.

## 2. Configuration location and posture

- Path: `${MATRIX_HOME}/providers.json`, using `matrixHome()` from `lib/session.mjs`
  (`MATRIX_HOME` env var, else `~/.matrix`).
- Directory created `0o700`; file created `0o600`. Reads are bounded to
  `1_048_576` bytes; a larger file is rejected without being parsed.
- Reject symlink or non-regular targets via `lstat` before reading or replacing.
- Nothing is loaded from the repository, model output, remote catalogs or plugins.
- A missing file is a valid empty configuration (`status: "missing"`), not an error.
- An invalid file never prevents Local Forge from starting: `loadProviderConfig()`
  returns `status: "invalid"` with a sanitized error. **Explicit** use of that
  configuration throws `CONFIG_INVALID`; it is never silently treated as empty.
- Persisted bytes never contain credentials. Auth is `{type:"bearer", env:"NAME"}`,
  `{type:"none"}` for keyless servers, or the internal `{type:"builtin"}` only on
  resolved built-in targets (never persisted).
- No raw-key CLI option, no header map, no arbitrary request-body override.

## 3. Schema (version 1, unknown fields rejected)

```json
{
  "schemaVersion": 1,
  "providers": [
    {
      "id": "lab",
      "name": "My inference server",
      "transport": "chat-completions",
      "baseUrl": "https://inference.example/v1",
      "auth": { "type": "bearer", "env": "LAB_API_KEY" },
      "defaultModel": "vendor/Model-X:latest",
      "allowInsecureHttp": false,
      "request": { "tokenLimitField": "max_tokens", "includeUsage": false },
      "models": [
        {
          "id": "vendor/Model-X:latest",
          "name": "Model X",
          "contextWindow": null,
          "pricing": null,
          "capabilities": { "tools": "unknown" }
        }
      ]
    }
  ]
}
```

Defaults applied while validating: `name` = `id`, `transport` = `chat-completions`,
`defaultModel` = `null`, `allowInsecureHttp` = `false`, `request` =
`{tokenLimitField:"max_tokens", includeUsage:false}`, `models` = `[]`,
per-model `name` = `id`, `contextWindow` = `null`, `pricing` = `null`,
`capabilities.tools` = `"unknown"`.

Ceilings: 1 MiB file, 64 profiles, 256 models per profile, provider ID ≤ 64 chars,
model ID ≤ 512 chars, display name ≤ 200 chars, base URL ≤ 2048 chars, env name ≤ 128 chars.

## 4. Identity rules

- Primary identity is the tuple `(providerId, exactWireModelId)`, never the model ID alone.
- Provider ID: `^[a-z0-9][a-z0-9_-]*$`, ≤ 64 chars, no surrounding whitespace, unique.
  Reserved and rejected: `local`, `openrouter`, `ollama`. (The built-in local target uses
  provider `matrix` internally; it is not a configurable profile.)
- Wire model ID: 1–512 chars, no control characters (`U+0000`–`U+001F`, `U+007F`), no
  surrounding whitespace. Case, `/`, `:` and `.` are preserved byte-for-byte.
- Duplicate model IDs within one profile are rejected; duplicate profile IDs are rejected.
- `transport` is the closed enum `["chat-completions"]`. Unknown transports fail; they do
  not fall back to another adapter.

## 5. Base URL rules

- Parsed with the URL API; `https:` always allowed.
- `http:` allowed only for literal loopback hosts (`localhost`, `127.0.0.1`, `::1`,
  bracketed IPv6 loopback) or when `allowInsecureHttp: true`. Otherwise
  `PROVIDER_INSECURE_HTTP`. Loopback is matched on the parsed hostname, never by
  substring.
- Rejected: URL userinfo, query string, fragment, non-http(s) schemes, surrounding
  whitespace, length > 2048.
- `baseUrl` is the API directory. A path already ending in `/chat/completions` or
  `/models` is rejected with `PROVIDER_FULL_ENDPOINT_URL`; the transport appends
  exactly one suffix.
- Normalization removes trailing `/` characters from the parsed `href` path and keeps
  any other prefix (`/team/v1` stays `/team/v1`).
- An insecure-http profile produces a visible warning string; it is not a sandbox policy.

## 6. Canonical digests

Canonicalization is recursive JSON with lexicographically sorted object keys, preserved
array order, `JSON.stringify` scalar encoding, then SHA-256 hex.

`configurationDigest(config)` covers the entire validated file
(`schemaVersion` + ordered `providers` array). It is the optimistic-concurrency token for
`expectedDigest` and the discovery-cache invalidation key.

`targetDigest(target)` covers exactly:

```json
{
  "version": 1,
  "providerId": "lab",
  "transport": "chat-completions",
  "baseUrl": "https://inference.example/v1",
  "auth": { "type": "bearer", "env": "LAB_API_KEY" },
  "request": { "tokenLimitField": "max_tokens", "includeUsage": false }
}
```

`modelId` is deliberately excluded: sessions persist `(providerId, exactModelId, digest)`
separately. No key material, catalog contents, probe results or display names enter either
digest, so a key rotation does not invalidate a saved session while an endpoint, auth
reference or request-option change does.

## 7. Selection precedence (executable in `resolveProviderSelection`)

| Invocation                                    | Resolution                                                                                               |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `--provider lab --model 'a/B:tag'`            | Exact ID on profile `lab`, even when absent from the catalog                                             |
| `--provider lab`                              | `defaultModel`, else `PROVIDER_NO_DEFAULT_MODEL`                                                         |
| No provider, `--model` alias                  | Existing legacy behavior via `resolveModel()` (Local Forge fallback)                                     |
| No provider or model                          | Local Forge                                                                                              |
| Unknown provider / unsupported transport      | Throw; never fall back                                                                                   |
| Explicit profile plus global endpoint/key env | Profile wins; legacy globals are not consulted                                                           |
| Explicit built-in model                       | Legacy credentials policy binds it; `MATRIX_API_BASE`/`OPENAI_BASE_URL` are not consulted for OpenRouter |

`resolveProviderSelection` returns `{target, warnings}` and does not throw for a
missing bearer key. Availability is a separate boolean-only query,
`isProviderCredentialAvailable(target, env)`, so the UI/doctor can show honest state
(`true`, `false`, or `null` for built-in targets whose legacy policy PRV-102 owns).
Headless execution fails before fetching via `resolveProviderCredential(target, env)`
→ `PROVIDER_MISSING_KEY`. The credential value is returned only to the run transport
and never enters a descriptor, event, session or error.

Resolved target shape (frozen, deep-frozen, JSON-serializable, no secrets):

```js
{
  kind: "local" | "builtin" | "custom",
  providerId: string,
  providerName: string,
  transport: "local" | "chat-completions",
  baseUrl: string | null,
  modelId: string,
  modelName: string,
  auth: {type:"bearer", env:string} | {type:"none"} | {type:"builtin"},
  request: {tokenLimitField:"max_tokens"|"max_completion_tokens", includeUsage:boolean},
  capabilities: {tools:"supported"|"unsupported"|"unknown"},
  contextWindow: number|null,
  pricing: {input:number, output:number, cacheRead:number}|null,
  configDigest: string|null,
  legacy: boolean
}
```

Built-in targets carry `auth:{type:"builtin"}`, `configDigest:null`, `legacy:true`; PRV-102
owns the adapter that maps them onto the existing credential policy.

## 8. Writer protocol

Mutation is serialized by a lock the **kernel** holds. The earlier lock-directory
protocol reclaimed stale locks by renaming the path; review R2 showed that a delayed
reclaimer can rename a lock a new owner just created, admitting two writers. Reclaiming
a name that can be recreated cannot be made race-free, so the protocol no longer
reclaims anything.

1. On Linux the lock is an abstract Unix socket:
   `\0matrix-provider-config-<sha256(dev:ino of the config directory)[0:40]>`. `bind` is
   the atomic acquisition; a second binder receives `EADDRINUSE`. The kernel releases the
   name when the owning process exits, so a crashed writer recovers immediately and there
   is no stale lock to steal. Contenders retry at 15–40 ms with a bounded total wait
   (default 5 s; injectable for tests). Exhaustion → `CONFIG_LOCKED`, no write.
   Keying on the directory identity, not its lexical path, makes a symlinked or otherwise
   aliased Matrix home share one lock; otherwise two spellings of the same file would
   admit two writers and lose an update. The identity is re-derived after binding and
   again immediately before the replacement rename; a changed directory identity aborts
   the mutation with `CONFIG_CONFLICT` and leaves the prior file untouched.
2. Platforms without abstract sockets use a private `${configPath}.lock` directory
   (`0o700`, `owner.json` with pid/token/host). The fallback never reclaims either: a
   live owner blocks until the deadline, and a dead owner produces `CONFIG_LOCKED`
   naming the directory to remove after the operator verifies no Matrix process is
   running. A paused owner can be alive, so owner age and PID liveness alone never
   justify removing a lock.
3. Inside the lock: bound-read and parse the existing file; compare
   `configurationDigest(current)` with `expectedDigest` when provided. Mismatch →
   `CONFIG_CONFLICT`, no write. Invalid existing file → `CONFIG_INVALID`, no write.
4. Mutation validates the complete new document, serializes it exactly once, and
   rejects `CONFIG_TOO_LARGE` before touching the target when the persisted UTF-8 byte
   length (including formatting and the trailing newline) would exceed 1 MiB. Otherwise
   it writes a same-directory temp file with `O_CREAT|O_EXCL`, `0o600`, `fsync`s it,
   renames atomically, and best-effort `fsync`s the directory. Any failure unlinks the
   temp and leaves the prior file valid.
5. Release closes the socket (or removes the directory only while the owner token still
   matches); a foreign lock is never removed. Process death releases the kernel lock;
   the fallback requires the documented manual recovery.

The mutation API is asynchronous (`addProviderProfile`, `replaceProviderProfile`,
`removeProviderProfile`, `addProviderModel`, `removeProviderModel`, and both lock
functions return promises) because kernel-held acquisition is asynchronous. Read-only
loading remains synchronous.

Read-only loading takes no lock and cannot block writers.

## 9. Error codes (closed set exported as `PROVIDER_ERROR_CODES`)

`CONFIG_TOO_LARGE`, `CONFIG_INVALID_JSON`, `CONFIG_UNSUPPORTED_SCHEMA`, `CONFIG_INVALID`,
`CONFIG_LIMIT_EXCEEDED`, `CONFIG_SYMLINK`, `CONFIG_NOT_REGULAR`, `CONFIG_LOCKED`,
`CONFIG_CONFLICT`, `PROVIDER_INVALID_ID`, `PROVIDER_RESERVED_ID`, `PROVIDER_DUPLICATE`,
`PROVIDER_UNKNOWN`, `PROVIDER_NO_DEFAULT_MODEL`, `PROVIDER_INVALID_MODEL_ID`,
`PROVIDER_DUPLICATE_MODEL`, `PROVIDER_INVALID_BASE_URL`, `PROVIDER_INSECURE_HTTP`,
`PROVIDER_FULL_ENDPOINT_URL`, `PROVIDER_UNSUPPORTED_TRANSPORT`, `PROVIDER_INVALID_AUTH`,
`PROVIDER_INVALID_REQUEST_OPTION`, `PROVIDER_MISSING_KEY`.

Errors are `ProviderError` instances with `code`, `message` and optional `details`
(`{path, ...}`). Messages must never echo raw invalid input that could be a credential;
field names and bounded lengths are sufficient diagnostics.

## 10. Migration and compatibility

- No session schema change in PRV-101. Sessions keep storing model IDs until PRV-104
  writes `(providerId, modelId, digest)` and migrates recognized legacy IDs.
- No CLI flags are added in PRV-101; `--provider` belongs to PRV-104. The precedence
  function is testable without touching `lib/cli.mjs`.
- Existing `resolveModel`, `getOpenRouterKey`, Local Forge and Ollama behavior are
  characterized by their current tests and were re-run unchanged at this baseline
  (574 tests, 0 failures, Node 24.21.0).

## 11. Test-only injection boundaries

`loadProviderConfig`/mutation accept `{home}` (isolated temporary Matrix home) and mutation
accepts `{lockTimeoutMs}`. `acquireProviderConfigLock` and `releaseProviderConfigLock` are
exported for subprocess crash tests; they are not wired into any production caller. The
`lockStrategy: "directory"` seam exercises the non-Linux fallback on Linux; kernel locking
is the only default. Tests use environment objects and fake key names only; no test reads
the real `~/.matrix`.
