# DUR-002 authoritative goal store

Status **ACCEPTED** for the Linux store boundary on base `ff55a2c`.
The [submission](../submissions/DUR-002.md) records the candidate, independent
verdict and engineering results.

`createGoalStore(matrixHome)` is an internal Linux API for an existing private
Matrix home. `create(record)` accepts a fresh ready goal at generation and sequence
zero. It syncs a canonical initial journal and checkpoint before publishing the
entire goal directory. Directories use mode 0700 and state files use 0600.

Use `withGoalLock(workspace, callback)` for synchronous store mutations. The lock
shares the canonical Linux workspace lock with model-agent writers. Its token
expires when the callback exits. The store checks the current root device/inode,
the actual process identity from procfs, the persisted lease and the exact
generation/sequence fence. A second, private store lock serializes quota checks
and commits. The lock order is workspace then store. Goal creation and staging
cleanup need only the store lock. An active attempt also reserves its workspace
against other goals in the same store. A dead owner's lease never grants the
next process write authority.

`beginAttempt` commits the new generation and lease before returning. `append`
validates intent, dispatch and receipt records against the committed chain. Intent
reserves budget and verifies recovery blobs. Dispatch checks that the same intent
and its blobs are present. A receipt binds to its dispatch and records observed
charges without releasing uncertain reservations. `transition`, `renew` and
`amendBudget` persist lifecycle, lease and budget updates under the same fence.
The caller remains responsible for verifying real effects, approvals and evidence.

An update syncs any missing content-addressed blobs, retains the current checkpoint
as the previous checkpoint, appends and syncs its journal frame, then atomically
publishes and syncs the new checkpoint. The checkpoint binds the goal and ledger
to an exact journal prefix. A caller may act on a successful update only after the
function returns. Any publication error stops the caller. An error after rename
can leave a visible checkpoint, so callers must reopen and verify instead of
blindly retrying the original operation.

`inspect`, `readJournal` and `readBlob` validate bounded state without writing.
They use pinned directory descriptors, reject unexpected links and nonregular
files, and verify checksums. `inspectPrevious` exposes the previous verified
snapshot as recovery evidence. It grants no writer authority. A suffix beyond
the current checkpoint is reported and retained, and subsequent updates refuse
until recovery resolves it. Missing or corrupt committed bytes require refusal.

The store enforces per-record, journal, blob and aggregate byte limits and bounds
inventory scans. Admission reserves journal bytes and records, store bytes and
inventory entries for pending receipt metadata and for stopping and cancellation.
The checkpoint records the pending receipt count so other goals preserve that
capacity. An active checkpoint without the count is replayed to derive it. New
optional evidence blobs need separate available capacity. No automatic pruning
removes published checkpoints, journals or blobs, including unreferenced blobs.
`cleanupStaging` only removes private unpublished creation directories and
recognized temporary files while holding the store lock.

The test matrix covers verified reopen, private modes, invalid IDs and unsafe
paths, FIFO and oversized reads, corrupt committed state, retained uncommitted
tails, exact recovery images, stale fences and leases, root replacement, real
lock contention, quota pressure, ENOSPC during a partial append, journal fsync
failure, checkpoint rename failure and SIGKILL at publication boundaries. These
are Linux process-crash tests. Filesystem and hardware power-loss behavior has
not been tested.

The store is internal. DUR-003 owns interpretation and repair of interrupted
effects and tails. DUR-004 and DUR-005 own execution and verified process-tree
reclamation, including holding workspace authority through worker teardown.
